    Search syntax

    Free text matches artist, title, difficulty, mapper and the mod string, everything is case-insensitive, and several terms are ANDed. A field form is field<operator>value with =, :, ==, !=, <, >, <=, >= — the same shape as osu!'s beatmap search. Quote a value with spaces: title:"blossom of ashes".

    = and : are fuzzy: for a text field the value is a case-insensitive substring, and for mod/mods it means “this score carries that mod”, so mod=DT also finds DT+MR. == is exact: the whole text value has to be equal, and mod==DT matches only a score whose mods are exactly DT. On a numeric field the two are the same, because a substring of a number is not something anybody means.

      How the weighted total builds up

      the 0.95-decay sum over the best N scores, so the height of the plateau is the total and the slope is how much each score still adds

      Pp per star

      A's pp divided by the score's star rating, one dot per score; the bigger the dot the more the two sides disagree, and a hollow dot means B pays more
